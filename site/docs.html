The calm manual

Everything you need to give a spare screen a job: what Dayboard is, how to install it by hand or hand the whole thing to your coding agent, and the answers to the questions everyone asks first.

Getting started #

What is Dayboard?

Dayboard is a personal dashboard for a display you already own — an old laptop, a spare panel wired to a home server, a Pi with a screen. It shows a big clock, today's tasks, your schedule, alarms and reminders, a pomodoro focus timer, and a quiet corner with a calendar, weather, notes and a task-activity heatmap.

It is server-authoritative: one zero-dependency Node file owns all state and timers, and every client (the kiosk display, your phone at /remote) subscribes to a live event stream. Switch a page on the phone and the display follows; dismiss an alarm on the display and the phone knows.

The sky is the soul of it: a gradient that follows your clock from dawn to dusk, and a night sky with stars, shooting stars and the occasional aurora.

Requirements

ThingWhat you need
ServerNode.js 18 or newer, anywhere: LXC, VM, container, bare metal. ~60 MB RAM in practice.
DisplayAny modern browser. Chromium in kiosk mode is the intended life.
Phone remoteAny device on the same Wi-Fi, any browser. No app install.
Host agent (optional)Python 3 standard library only, on the machine physically attached to the panel (X11 + sysfs).
DependenciesNone. No npm install, no build step, no database.

Quick start

Thirty seconds to a running dashboard on any machine with Node:

shell
git clone https://github.com/Saiwilan/Dayboard.git
cd Dayboard
node server.mjs

Open http://localhost:4000 for the display and http://localhost:4000/remote for the phone UI. First run seeds itself with demo content so you can look around before making it yours.

Your first run

  • Page 1 · Today — greeting, clock, tasks, up-next event and alarm. Space ticks a task off.
  • Page 2 · Schedule — a 12-hour day view with a live "now" line. , and . move between days.
  • Page 3 · Alarms — repeating alarms and one-shot reminders, with ringtones.
  • Page 4 · Focus — pomodoro with cycles and a session log. Space starts and pauses.
  • Page 5 · Extras — calendar, weather, notes from your phone, activity heatmap.
  • Page 6 · Settings — theme, sky mode, sun-path shift, volume, brightness, screensaver, name.

Press ? or H on the display for the full keyboard map. Everything you change on the phone appears on the display instantly.

Installation #

Two ways in: do it yourself below, or hand the prompt to your agent and let it drive. Both end at the same place — a systemd-managed server on port 4000.

Manual install

Proxmox LXC

A small unprivileged Debian container is the natural home. 512 MB of RAM is plenty.

on the Proxmox host
pct create 120 local:vztmpl/debian-12-standard_12.7-1_amd64.tar.zst \
  --hostname dayboard --memory 512 --cores 1 --rootfs local-lvm:4 \
  --net0 name=eth0,bridge=vmbr0,ip=dhcp --unprivileged 1 --onboot 1
pct start 120
pct enter 120

Adjust the template name to whatever pveam available lists on your host. Then inside the container:

inside the container
apt update && apt install -y nodejs git   # Debian 12 ships Node 18
git clone https://github.com/Saiwilan/Dayboard.git /opt/dayboard
mkdir -p /etc/dayboard && touch /etc/dayboard/env
cp /opt/dayboard/host/dayboard.service /etc/systemd/system/
systemctl enable --now dayboard
curl -s http://localhost:4000/api/state | head -c 120
Find the container's IP with pct exec 120 -- hostname -I, then open http://<container-ip>:4000 from any device on your LAN.

Any Linux or container

The same unit file works on any box with Node at /usr/bin/node:

shell
git clone https://github.com/Saiwilan/Dayboard.git /opt/dayboard
mkdir -p /etc/dayboard && touch /etc/dayboard/env
cp /opt/dayboard/host/dayboard.service /etc/systemd/system/
systemctl enable --now dayboard

No systemd? node server.mjs under your favourite process supervisor is equally happy. State lives in data/state.json next to the server.

Docker

Dockerfile
FROM node:22-alpine
WORKDIR /app
COPY server.mjs ./
COPY public ./public
EXPOSE 4000
CMD ["node", "server.mjs"]
shell
docker build -t dayboard .
docker run -d -p 4000:4000 -v dayboard-data:/app/data --name dayboard dayboard

The volume keeps your state across rebuilds. The host agent cannot live in this container — it belongs on the machine with the panel (see below).

Kiosk & host agent

On the machine attached to the display, point a browser at the server and lock it down:

on the display machine
chromium --kiosk --noerrdialogs --disable-session-crashed-bubble \
  --autoplay-policy=no-user-gesture-required http://<container-ip>:4000

Run it from an auto-login session or a systemd service so the dashboard survives reboots. Autoplay matters — alarms need sound.

The optional host agent adds real backlight control, display power, mute, and hardware alerts (ethernet, battery, temperature). On the display machine:

host agent
mkdir -p /etc/dayboard-agent
openssl rand -hex 16 > /etc/dayboard-agent/token
python3 /opt/dayboard/host/agent.py        # listens on :8009

# then in the server's /etc/dayboard/env:
DISPLAY_AGENT_URL=http://<display-host-ip>:8009
DISPLAY_AGENT_TOKEN=<the same token>

Restart the server afterwards. A ready-made unit lives at host/dayboard-agent.service. Without the agent, Dayboard is fully functional — the hardware controls simply stay hidden.

Ask your agent to install it

Prefer to delegate? Paste the prompt below into your coding agent of choice and let it do the whole install — container, Node, service, verification — while you make tea.

Open a Qoder chat in any workspace and paste the prompt as your message. Qoder will run the shell steps itself and ask before anything risky.

paste this into your agent
Install Dayboard (https://github.com/Saiwilan/Dayboard) for me.
Goal: a running Dayboard server on port 4000, surviving reboots, reachable on my LAN.

1. Detect the environment. If this machine is a Proxmox host, create a small
   unprivileged Debian 12 LXC named "dayboard" (512 MB RAM, 1 core, DHCP on my
   default bridge) and work inside it. Otherwise use this machine directly.
2. Install Node.js 18+ and git (Debian 12: apt install -y nodejs git).
3. Clone https://github.com/Saiwilan/Dayboard.git into /opt/dayboard.
4. Create /etc/dayboard/env (empty is fine), install host/dayboard.service as a
   systemd unit, then enable and start it.
5. Verify: curl -s http://localhost:4000/api/state | head -c 200 must return JSON.
6. Report the LAN URL (http://<container-ip>:4000) and the phone remote URL
   (same host, path /remote).
7. Only if I ask afterwards: set up a kiosk browser on the attached display, and
   the optional python host agent (host/agent.py) with a random token in
   /etc/dayboard-agent/token, wired through DISPLAY_AGENT_URL and
   DISPLAY_AGENT_TOKEN in /etc/dayboard/env.

Rules: never print secrets or tokens; use my existing SSH keys for remote hosts;
ask before deleting or overwriting anything; if a step fails, stop and report
instead of guessing.
The same prompt works in all three agents — only the way you hand it over differs. Switch tabs above for the hand-off.

FAQ #

Does Dayboard need the internet?+

No. Everything runs on your LAN. The only outbound call is weather from Open-Meteo, and only if you set a location in Settings. No accounts, no telemetry, no cloud sync.

Is it really zero dependencies?+

The server uses only Node built-ins (http, fs, path, crypto). The host agent uses only the Python 3 standard library. The QA scripts in qa/ use puppeteer-core, but that is dev-only and never needed to run Dayboard.

Which Node version do I need?+

18 or newer. Debian 12's apt install nodejs gives you 18, which is enough. There is no npm install and no build step.

Do alarms fire if no browser is open?+

The server owns all timers and fires alarm events to every connected client. The full-screen overlay and sound need a connected client — which is exactly what kiosk mode is for: leave the display browser open. Your phone remote rings and toasts too while it is open.

Do I need the host agent?+

No. Without it, brightness, display power, mute and hardware alerts stay hidden and everything else works normally. Add it later if your display machine runs Linux with X11 and you want the panel itself under control.

Where does my data live?+

In data/state.json next to server.mjs, written atomically. It never leaves the machine. Delete it to reseed the demo content; keep it to keep your day.

Can a phone or tablet be the display?+

Yes — any browser works. Open / for the display UI (great on a tablet propped on a desk) and /remote for the control UI. Both stay in sync with every other client.

How do I update?+

git pull in the install directory, then systemctl restart dayboard. Your state file is preserved and settings migrate automatically when new options appear.

Can I run several displays?+

Yes. Every browser showing / mirrors the same state and the same current page, so a kitchen panel and a desk panel stay in step. Page switches from any client — including the phone — move them all.
